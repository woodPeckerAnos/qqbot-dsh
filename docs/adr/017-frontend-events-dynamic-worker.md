# ADR-017：前台事件调度与按需 worker

状态：已批准，已实施。现行 V3 取代 ADR-001、ADR-004、ADR-006 中固定快慢双 lane 的执行和协作规则；V1/V2 声明、历史记录和测试继续保留。

每个有效输入创建一个 Task，首次只安排前台。前台拥有查询、取消和一次 worker 派发能力；worker 负责业务工具与交付物，结果交回原 Task 的新前台回合。首次前台、worker 和整理均拥有独立 job ID；同 Session 的前台串行，首次输入和结果整理交替，worker 在同 Session 内串行。普通话题变化保留旧 Task，`/stop` 取消已开始首次处理的所有未完成阶段，`/new` 取消全部未完成 Task。

TaskLifeCycleManagerV3 是执行状态唯一写者。领取、派发、结果、最终回复和入队确认都先保存再提交内存并通知。派发以规范化交接内容去重，同内容返回已有稳定回执，异内容拒绝；Task、权限、输入和附件由服务端绑定。接受 worker 后前台异常退出仍保留 worker，取消优先。完成通知仅用于唤醒，恢复和维护通过相同领取接口补遗漏。

worker 保存完整结果、证据、附件和未完成事项，失败及未知结果同样保留。保存结果同时进入待整理状态；首次前台彻底退出后才能整理。整理最多领取两次，仅可重试故障允许第二次；耗尽后保存固定失败说明，原始结果和附件保留。最终正文必须非空，附件由程序验证；固定 reply ID 入队后才结束 Task，实际送达状态独立由 MessageQueue 写入。

重启继续排队 worker，沿用原排队截止时间；已领取 worker 缺终态时保存中断或未知结果，禁止自动重跑。已保存结果继续整理，已开始整理计入两次上限，已固定回复仅补入队。未完成 V1/V2 任务按原中断规则处理，不能转成 V3 worker。持久记录沿用外层格式并逐条校验，V3 增加 schemaVersion:3，非法记录明确失败。

前台和 worker 共用原慢 lane 的有效模型路由，思考默认 high；前台每回合 30 秒，首次最多 3 step，整理关闭工具循环。排队和 worker 执行各自最多 30 分钟；运行额度各 4，总 runtime 上限 8，容量与保留沿用每 Session 32、全局 128、7 天。长任务承接语仅在派发已保存后尝试即时发送，存活提醒和主动预算继续按原 Task 结算。

保留固定双 lane 会让每次输入都创建昂贵业务执行，并把前台可用性绑到整轮协作等待。新选择由 worker 明确派发和状态交接承担协作；代价是增加持久阶段与补遗漏调度。若后续需要多个 worker，须新增契约版本和对应所有权规则，不能静默放宽 V3 的单 worker 不变量。
