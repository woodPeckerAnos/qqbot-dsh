# ADR-019：程序生成 worker 响应，模型只提交内容

状态：已批准，已实施。补充 ADR-017 的 worker 结果和整理协议，公共接口及持久记录保留 V3 形状。

真实 Qwen worker 完成计算并生成文件后，在最终 JSON 前添加说明和代码围栏。原实现对整段正文执行 JSON.parse，随后把格式问题记录为 failed，丢失独立证据并把内部校验信息传给整理模型。worker 和整理模型都不再负责生成整份结构化响应；正文直接作为内容，程序负责分类、错误说明和附件。

worker 内部回合结果区分成功 data、失败 failure/message/partialData 和已派发。程序根据 runtime、子代理结束及交付检查生成 WorkerResult，TaskLifeCycleManager 继续独占持久执行状态。正常结束记录 completed，模型写出的业务未完成说明作为正文保留，前台如实转告。空正文仍按运行结果分类，仅有附件可以整理；正文和附件都没有时，前台明确说明没有返回结果。不增加业务报错或结果提交工具，不解析正文中的状态或 JSON。

新结果的独立 evidence 只记录程序掌握的运行事实和实际文件检查，模型给出的引用、计算依据和未完成说明完整留在 text。不扩展命令执行证据采集，也不把工具调用计数当作业务成功证明。运行失败及附件检查故障保留已有正文和有效文件；取消和结果未知继续使用现有分类。历史结果及终态不重写。

取消先保存终态，原实现随后忽略 worker 收尾，导致部分材料丢失。现允许同一已绑定 worker 的 cancelled 收尾为当前空 cancelled 占位结果补存正文、有效附件和运行证据，保持 Task 终态、取消时间及 receipt 分类，不再整理或入队。不接受其他分类的迟到结果，不覆盖已有业务结果；重复提交幂等，保存失败仍先落盘再提交内存。该补存只保存材料，取消规则和执行身份匹配继续收紧。

整理模型直接返回非空最终正文，程序再次校验本次全部已保存附件并加入回复。outbox 继续只放最终交付物，删除附件 ID 选择协议。整理输入保留完整正文及已有证据、未完成补充材料，让旧 V3 待整理结果继续使用原有业务材料；程序统计不作为业务完成依据。排除原始异常、cause、errorId 和内部校验诊断，使用按失败类型生成的用户说明；提示要求保留未完成和不确定性，避免复述内部术语。重试上限、固定回复、幂等入队及实际投递状态的所有权继续沿用现有规则。

放宽 JSON 提取仍让模型承担响应结构，独立提交工具会增加当前不需要的业务失败协议。本次选择内容与程序响应分开，completed 记录运行正常结束。如果以后需要独立衡量业务完成率，应新增有明确来源的业务完成契约；如果 outbox 允许保留不发送的材料，再引入独立附件选择能力。

验收使用注入 DSH、连接器、时钟和真实本地文件的离线检查，覆盖说明加围栏 JSON、普通文字、正文里的失败状态、全部附件、空正文、运行故障、失效文件和恢复。真实模型复测需独立费用授权，不作为离线验证的一部分。
