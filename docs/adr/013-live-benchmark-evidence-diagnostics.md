# ADR-013：真实任务衔接的工具证据与裁判请求诊断

状态：接受；日期：2026-11-08。

## 问题与历史证据

ADR-012 首次 LC01–LC03 单次验证中，LC01 全部通过，LC02/LC03 的语义通过但原任务分别调用三次、两次 bash，违反一次工具生成的运行约束。随后六场景三次回归被中断，仅留下 10/18 个样本；其中八个裁判请求失败或超时。以上报告保留为失败/未完成，不重判、不补写成通过。

## 决策与 benchmark 内部契约

LC01–LC03 升级到 v2，原输入给出明确的单次 bash 命令，调用 node:crypto.randomUUID 生成并输出 receipt。仍要求原慢执行恰好一次 bash、零工具错误，后续请求无业务工具；不放宽原断言。实际 receipt 必须同时出现在所属慢执行的成功工具结果与最终正文，只有正文或工具名不足以证明来源。

RuntimeEvidence 从真实 tool/result 的 message.content 中识别 tool-result 错误标记，只提取其 text 块中的 UUID v4 值；不保留工具参数、完整工具输出或 reasoning 块。ADR-014 进一步限定为 receipt 标记后的编号，排除 Task/trace 标识。重复、错属、失败和迟到事件不能提供成功工具证据。报告和裁判输入保存 toolResultUuids；工具输出与正文不匹配、缺失或出现多个编号均阻断运行通过。

裁判评分、v6 rubric、校准 v3 和禁止自动重试保持不变。请求错误分别记录 judge-timeout、judge-http-<状态码>、judge-response-invalid-json、judge-response-too-large、judge-network-error；不记录响应原文、凭证、端点或底层异常文本。所有请求错误仍为 inconclusive，并阻断严格门禁。

校准开始及每个样本结束后持久化报告，校准完成前 passed 始终为 false。逐项回调接收隔离副本，不能改写校准判定；保存失败中止本轮并保留已写出的证据。中断的部分校准不能满足发布门禁，恢复时以新目录重跑完整校准。

## 验收

离线验证真实 SDK 工具结果形状、UUID 来源匹配、错误及跨会话/重复事件过滤、正文编造与额外工具调用拒绝，以及裁判超时、HTTP、网络、非法 JSON 的错误分类。另验逐项校准保存、中断与回调隔离。重新执行完整检查和 C01–C10 固定基线比较；使用新的报告目录运行 live 单次验证，再完成六场景各三次严格回归。历史报告单列，缺少样本不可标完成。

生产 Session、Task、投递与配置行为不变；没有新增生产公共接口。
