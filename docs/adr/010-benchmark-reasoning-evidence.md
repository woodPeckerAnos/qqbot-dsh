# ADR-010：benchmark 推理证据的适用范围

状态：接受；裁判 v5，在线效果待验收。日期：2026-11-08。

## 问题

ADR-009 的既有三次严格 live 报告 `tmp/session-context-live-final` 中，L13/L14/L18 共九个样本的运行检查全部通过，语义为六项 pass、三项 inconclusive。三项未定结论均将快 lane 的 reasoningTokens=0 当作推理证据缺失，虽然同一原 Task 的慢 lane 实际记录了 4390、4026、4490 个推理 token。

快 lane 按生产契约关闭推理；慢 lane 可以核对快答后以 no-increment 静默结束。推理是否发生与是否再次投递正文是两个不同事实，不能要求慢 lane 为证明发生过推理而重复发送答案。原报告保留原判定，不回写为通过。

## 决策与内部契约

benchmark 传给裁判的 `reasoningRequired` 显式取自场景的 `reasoning` 标记，运行报告保存此布尔值；旧报告缺少该字段时不推断或改写历史结论。裁判仅在此字段为 true 时执行推理元数据要求，不自行根据题目长度、公式或证明形式添加要求。现有需要推理证据的 L01/L02/L11/L12 保留要求。

证据按 Task 身份读取其 slow lane 的 reasoning 事件或正数 reasoningTokens；不能借用其他 Task、快 lane、答案长度或工具调用替代。慢 lane 静默不使已记录的推理证据失效。元数据只证明推理发生，不证明答案正确；语义、可信度与真实交付仍独立评测。

裁判升级至 v5，校准集升级至 v2：保留原六个样本及其标签，增加无需推理的快答、慢 lane 有证据但静默、要求慢推理但仅快 lane 有证据三个样本。最后一项必须得到 trust=inconclusive，前两项应通过；不匹配仍阻断业务样本。预期 inconclusive 的校准样本也必须收到结构合法、无请求或解析错误的裁判结果，超时或畸形输出不算正确识别缺证据。runner 对标记场景缺少慢 lane 证据的确定性拦截保留，不把模型裁判的 pass 当作证据。

## 验收

使用注入 HTTP 裁判验证请求数据、三类校准结果及错误判定拒绝；验证仅快 lane 证据无法通过 runner 的推理检查，慢 lane 静默的实际元数据可以满足证据要求。类型、lint、完整离线与契约门禁重新运行。

新规则需要新一轮显式 live 校准及 L13/L14/L18 三次严格回归；离线测试不证明真实裁判遵循规则。生产 Task、SessionContextView、调度、投递和配置行为不变，不增加生产公共接口。
