# ADR-001：Task、双 lane 和独立投递

状态：已实施并通过本地验收。

问题：整轮 Session 锁阻塞新输入；后台派发后提前结算导致执行归属丢失；发送与执行混用状态，导致失败重发和跨话题扣费。

决策：每输入创建一个 Task，两个独立 lane 完整执行；管理器唯一写状态。每次执行绑定 runtime 租约、generation 和唯一 sessionId，先注册再派发，迟到事件隔离。按 Task 保存工作目录与可靠附件引用。消息队列独立持久化、按尝试一次投递，失败通知一次。原引用和可变发送锚点分离，主动预算按 Task 结算。

后果：允许同 Task 的两个不同结论；不增加模型整理调用。发送可以在执行结束后等待出口，已尝试消息不会自动重发。冷启动将未完成 Task 标为中断失败，形成一次失败结果。

验收：见 [模块契约](../MODULE-CONTRACTS.md)、[验收记录](../TASK-STATUS.md) 与 `tests/task-system.test.ts`。唯一入口已替换，旧整轮锁、后台自发结果协调、周期进度仅作为 `tests/legacy/` 的历史回归夹具保留，不参与生产装配。
