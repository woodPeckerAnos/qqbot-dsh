# ADR-007：Task 输出记录与附件归并

状态：已实施，离线及 localhost WebSocket 验收通过（2026-11-07）。优化前动作基线已保存；实施和验收记录见 SESSION-BENCHMARK，QQ 客户端展示与播放尚未实测。

## 背景与历史

历史 Responder 曾提供多文件 ZIP；现行 src/main.ts 的 Task 出口没有使用该交付路径，而是分段正文及逐附件说明。ADR-006 的执行和投递所有权继续有效。

## 决策

OneBot 群聊和私聊声明可选 record 能力。短正文一条；超过该平台 maxChars 的正文用短提示和一条合并转发记录。多个图片/MP4 视频放入同一平铺记录，有正文时按正文、媒体顺序排列，短提及/引用另外发送。单附件保留原文件，长正文和单图片/MP4 可以合并。多个普通文件或混合附件全部打为一个 ZIP，正文独立；长正文加 ZIP 共三条。官方 QQ 及未声明能力的连接器保留既有方式。

声明 record 能力时，成功执行的 NO_REPLY 如果产生附件，转为正文为空的 reply 并实际交付文件或媒体记录；这不属于静默。未声明能力的旧路径继续要求附件说明。执行失败、无效交付物、超时和真正空结果仍按原错误契约处理。

记录节点仅支持文本、图片、视频，不嵌套记录。保留原始正文分段及节点映射，跨 lane 去重在包装前仅消费成功送达分段；提示、附件和失败通知不算原正文。记录的 text 保留完整原正文供历史和观察窗口读取，协作快照展开映射分段。用户触发的群交付提及原提问者，私聊和主动请求不提及；原输入引用独立于发送锚点，缺失 ID 用短摘录。

协调器先准备独立文件副本，后以稳定 ID 一次持久化完整交付组，保存失败不留下半组、不发起平台动作。MessageQueue 唯一写入投递状态，组内按序尝试（前项终结后推进，失败不撤回后项），不同 Task 不相互等待；文本、记录和附件使用独立 Session 通道。失败、超时、重启结果未知不重发，每个交付组最多一条失败通知；通知不携带记录、附件、正文标记或组依赖。

ZIP 使用现有 store-only 打包器，不截断、不省略条目；条目同名时确定性改名避免解压覆盖。单文件及 ZIP 遵守 media.maxFileBytes。图片沿用既有扩展名白名单，视频只按 MP4 扩展名识别，无转码。记录发送前检查完整序列化 OneBot 帧不超过 100 MiB（能力上限可下调，不能抬高硬上限），包含 base64 膨胀；超限由队列终结并明确通知，不拆记录、不截正文。准备失败作为候选投递错误由队列结算。

群/私记录分别调用 send_group_forward_msg / send_private_forward_msg，每个媒体独占一个 node，发送者使用连接器学到的 self_id，编码复用 base64/path。

## 验证

先以同一 Harness 注入 DSH、连接器和时钟，通过真实 OneBot 适配器注入 transport 保存优化前动作。输出组版本、种子和输入哈希固定；严格比较展示规则、正文完整和每个附件及 ZIP 条目 SHA-256，耗时只记录。另测记录阻塞期间新快回复、原引用和新锚点、成功与失败去重、清理独立文件、未知结果恢复、载荷上限与通知幂等。npm run check 和独立 test:integration 必须完成。真实 QQ 图片展示和 MP4 播放需客户端单独验收，离线动作不能证明。
