# ADR-005：SessionActor 应答链路 benchmark

状态：benchmark 已实施（2026-11-06）；本文原始生产现状为历史记录，当前协作策略见 ADR-006。真实模型评测是否完成以运行报告为准。

## 现状与问题

当前 SessionActor 原子准入双 lane，快慢独立调度；DshLaneRunner 验证正常静默、业务执行后静默、空结果和子代理失败，出口只对同 Task 完全相同正文去重。不同措辞的重复答案，以及快回复终局否认、慢回复随后给出完整解，仍可能直接送达。这些是已知缺口，不是已经实现的语义保证。

## 决策

增加两层 benchmark：离线层通过公共工厂装配真实输入、Actor、调度、DSH runner、出口和队列，注入 DSH、连接器、话题判定、时钟和存储故障；真实层保留实际 TaskSystem、DSH、路由、profile 和思考参数，仅以内存连接器替换 QQ 收发。每个样本使用独立临时状态与工作区，多轮样本内部保留上下文。真实 WebSocket 仍是独立集成检查。

内部场景、运行记录、断言和裁判类型不进入生产公共 API。运行断言依据状态和平台动作；语义评测依据用户实际收到的完整有序序列，保留分段、附件、提醒、引用和 lane 原始最终结果。思考只记录事件是否出现与 token 数，不保存思考正文。

目标：短任务直接回答、慢 lane 静默；长任务快回复承接、慢回复增量交付。同主题的实质补充、明确说明继续处理和有解释的结论修正可以通过；实质重复或无解释的终局否认反转失败。文本相似度不能作为语义合格依据。

裁判使用独立端点、模型与 apiKeyEnv，固定准则及标注样本校准。畸形、超时、缺证据和校准失败不能通过。默认记录语义失败但拦截运行约束失败；严格模式拦截严重语义失败与必要评测未完成，已知问题不豁免。性能只记录基线，不编造毫秒门槛；容量、FIFO、跨 lane 推进、重复发送、预算守恒和关闭释放是硬检查。

## 契约与验收

生产契约签名及行为保持当前版本，生成的 MODULE-CONTRACTS 不加入目标保证。benchmark 的内部记录契约、配置、场景、门禁与命令见 [验收说明](../SESSION-BENCHMARK.md)。离线验收纳入 npm test / npm run check；显式在线配置缺失返回失败，禁止静默跳过或自动重跑失败样本。

本次不修改 lane 提示词、出口策略，不部署。

## 裁判规则澄清（2026-11-07）

首轮 DeepSeek 官方 live 校准发现，原准则将短任务慢 lane 静默写成无条件要求，导致正常承接和必要的明确纠错被判为 handoff 失败。校准样本及其标签保持不变，首轮失败报告保留。

裁判 v2 按 ADR-006 的无增量条件评测：快答已正确完整满足请求、无需纠错或补充时，慢 lane 应静默；有解释的必要纠错、实质补充以及承接后完成请求，均为有效衔接，适用于简单问题。不得仅凭问题看起来简单否定已经完成的有效衔接。重复答案、无解释反转、虚假交付及证据不足的标准保持原有门禁。变更仅影响 benchmark 内部裁判准则及版本指纹。

裁判 v2 首次业务运行的七个样本中，运行断言全部通过，六项语义通过，L02 的裁判格式或引用未通过校验，严格门禁如实失败。裁判 v3 使用 chat/completions 的 JSON object 输出模式，明确要求引用逐字保留标点与公式反斜线，并区分非法 JSON 与引用校验错误。仍不修补或接受畸形内容，不放宽逐字证据要求，不重试同一样本；旧报告保留，新版本另开一轮验证。

后续 v3 校准曾把无解释的终局否认反转判为通过。裁判 v4 明确：有效纠错必须回指先前快答并撤回或纠正错误，解释冲突原因；仅提供新答案的解题步骤不构成对先前否认的解释。四个维度独立判分，正确终局答案不豁免 contradiction。校准样本、标签和门禁保持不变，错误校准继续阻断业务样本。
