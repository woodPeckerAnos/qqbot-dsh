# ADR-018：启动期模型检查与旧任务中断通知

状态：已批准，已实施。补充 ADR-017 的初始化与 V1/V2 恢复规则。

共享任务模型默认 high；本机 qwen-token-plan/qwen3.8-flash 仅支持 low、medium、xhigh，使用 medium。显式模型目录继续由配置解析校验；继承 DSH 目录时，每次启动用最终模型选择与相同 patch 顺序执行一次 frontend initialize，不调用 prompt。检查成功并关闭临时 runtime 后，才恢复人设、构造连接器和恢复 TaskSystem。失败不自动降档、不重试，清理临时工作目录并退出；初始化超时和关闭时限沿用现有配置，取消信号贯穿握手。

仅修正本机档位会继续把其他目录配置错误拖到首条消息。启动检查增加一次进程初始化，换取接收消息前发现错误；它检查目录、profile 和初始化能力，真实服务响应仍由独立集成验证。如果任务阶段未来使用不同模型，必须扩展检查覆盖对应的最终选择。

升级时未完成 V1/V2 任务继续按中断失败处理，不转换成 worker。TaskSystem 先通过 MessageQueue 保存固定 ID `<taskId>:restart-interrupted` 的通知，再由 manager 保存旧任务 failed 状态，最后结算预算。队列保存失败保留旧状态；旧任务保存失败，下次启动复用消息 ID 补状态。已完成 lane 结果保留，已有终态旧任务不追补通知，通知投递失败不派生额外通知。无需改变持久化格式。

消息与 Task 分别持久化，先标失败再保存通知会在崩溃时永久丢失通知。先保存通知允许恢复重复执行，固定 ID 消除重复入队；官方出口过期时继续等待新合法出口，实际投递状态仍由 MessageQueue 写入。
