# ADR-022：取消范围与“已停止”的真实含义

状态：已实施并通过离线验收。补充 ADR-017、ADR-020、ADR-021；不改变 Task 终态与 schemaVersion 3。

## 问题与证据

2026-11-27 测试环境：

1. **普通成员无法停止主动 Task**。Task `63121e7f`（用户“你不要查可以吗”）查询到 `d6e375b1` 仍在 `worker-waiting`，随后调用 `cancel_task`，收到 `NOT_FOUND`。`d6e375b1` 是 `source=proactive`，其 `input.message.senderId` 是合成上下文的 `context`；`canCancel` 只允许管理员或“目标 Task 的原发送者”，于是普通成员无法停止由自己参与的话题触发的主动任务。该 Task 随后继续执行到 17:02 并送达结果。
2. **“已停止”被说成“不会再有结果”**。Task `b8f472ff` 取消 `59692d4b` 成功（`{ok:true,value:true}`），回复却说“已经把它停掉，不会再有结果发过来”。取消只停止未完成执行；已入队消息、已在途 runtime 结果以及同一问题的其他 Task 仍可能送达，这个承诺过强。
3. **`/stop` 的现状**。原实现把 `/stop` 和 `/new` 一起做了管理员校验；测试环境的所有成功记录发送者都是 `BOT_ADMINS` 中的管理员，普通成员只能走自然语言 `cancel_task`。本次把 `/stop` 开放给所有成员，但按身份过滤范围。

## 决策

### 1. 取消权限按 Task 来源分层

`canCancel` 改为：

- 同一会话，且目标 Task 的 `creationSequence` 早于当前 Task；
- 管理员：可以取消；
- 普通成员：可以取消自己发起的用户 Task，或**同一会话内尚未回复的主动 Task**；
- 不再要求 `generation` 相同：上下文刷新后，旧 Task 仍可能运行，用户应当能停止它；
- 已取消或已终结的目标仍返回 `value=false`，不伪装成功。

主动 Task 没有“发起用户”：它的 sender 是触发时选中的原消息或合成上下文。普通成员停止主动工作时，风险是“少说一句”，低于管理员兜底的成本；用户 Task 仍保留发送者边界。

### 2. 取消话术必须保留“仍可能送达”

前台指令新增：取消成功只能说“已请求停止 / 已停止后续执行”，不得承诺“不会再有结果”或“已彻底停掉”；`value=false` 表示任务已结束或没有可停止执行，按真实状态说明。取消只停止未完成执行，已入队消息和在途结果继续由队列投递。

### 3. `/stop` 对所有成员开放，但按范围过滤

`SessionCommandRouter` 不再对 `stop` 做管理员拒绝：管理员调用 `actor.stop(sessionKey)` 取消整个会话；普通成员调用 `actor.stop(sessionKey, trace, senderId)`，只停止自己发起的 Task 和本会话的主动 Task。`/new` 仍只允许管理员，因为它会重置上下文并取消全部未完成 Task。

普通成员看到的回执是“已停止你发起的任务和本会话的主动任务，其他排队任务保留”；没有可停止对象时说“当前没有你可停止的任务”。

## 验收

- 单测覆盖：普通成员可取消主动 Task；不能取消别人发起的用户 Task；本人任务和管理员取消；未来 Task、跨会话、已取消 Task 拒绝。
- `/stop`：普通成员传入 sender 过滤，管理员不传 sender；`/new` 对普通成员仍拒绝。
- 前台提示包含“已入队/在途仍可能送达”“不得承诺不会再有结果”“value=false 的真实含义”。
- `npm run typecheck`、`npm test`（69 个文件、1185 项通过、44 项跳过）、`npm run contracts:check`、`npm run lint` 通过；真实容器重建与现网复验另列。

## 后续

- 取消成功后仍建议在 Task 记录中区分“执行已中止”和“仅保存了终态”，当前队列不等待 worker 的实际退出；这是后续可观测性改进。
- 主动 Task 的取消范围是“同会话”，不是“同发起人”；这是有意的低风险取舍，后续若出现滥用再加成员/群管理员白名单。
