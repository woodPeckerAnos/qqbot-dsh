# ADR-021：主动引用、问答去重与长回复表达

状态：已实施并通过离线验收。补充 ADR-017、ADR-019、ADR-020；不改变 Task 所有权、schemaVersion 3 与公共入口。

## 问题与证据

测试容器 `qqbot-dsh-test`（镜像构建于 2026-11-25 15:56）在 2026-11-26 至 11-27 的 Task 记录显示三类可复现问题：

1. **主动介入答错对象**。scene-3 的「当前唯一 Task 输入」只写入 `任务`（directive）与 `触发依据`（例如 `q:539205223@1795669718000`），没有写入被引用的提问正文。前端无法把 `q:<id>@<ts>` 映射到具体消息，只能从背景窗口里挑一条相关问题回答，于是出现引用「武侠小说为什么不火」却回答「人是不是一生下来就必须劳动」、引用「西游记换演员」却回答「达里奥套现」这类错位。`q:` 标识只存在于判定层，不在前端背景里。
2. **同一挂起问题被多次主动回答**。问题台账在主动 Task 成功准入后没有关闭；`maxQuestionProbes=2` 与后续人类消息会再次武装探针，导致同一 `q:<id>` 在数分钟内生成 2–3 个 Task。实测 `q:539205223` 产生 3 个 Task（两次答劳动、一次答蓝色星原），`q:757006730` 产生 2 个 Task，均实际送达。
3. **长回复缺少索引**。正文超过 OneBot `maxChars=1500` 时走合并转发，前置提示固定为「结果已整理，请查看下面的消息。」；完整正文（常见 3000–9500 字）只能在记录里打开。引用摘录未截断，scene-2 的合成上下文引用会把最近 4 条消息整段内联进回复正文。

此外，当前「前台处理失败，请稍后重试。」只剩一类现网触发：图片「真的假的」触发上游内容安全过滤，DSH 返回 `PI_AI_ERROR: Output data may contain inappropriate content.`；`TurnAccumulator` 已保存 `errorMessage`，但 runner 的失败 cause 丢弃了它，前台只能发固定失败文案。

## 决策

### 1. 主动 Task 的当前输入必须带原引用

`PromptPreparer` 为 proactive Task 组装的当前输入增加「原引用消息」：发送者与正文（上限 600 字，截断显式标注），并声明这是第三方内容、只作为回答对象。正文之后明确要求「只回答这条原引用消息；背景里其他挂起问题不是本次目标，不要改答」。原引用缺失时才退回只给 directive/evidence。

### 2. 引用按「对象」解析，而不是按场景默认值

`ProactiveWatcher.deliver` 的选择顺序改为：

1. wait 目标（`q:<id>@<ts>`）在消息窗口中的精确命中；
2. 其余场景按 `decision.evidence` 在窗口中回查（双向包含，evidence 去掉 `(对我说的)` 与 `发送者：` 前缀；正文至少 4 字）；
3. scene-1 / scene-4 的最后一条人类消息；
4. 合成上下文（保留，但只作为最后兜底）。

这样 scene-1 的「纠错对象」和 scene-2 的「被回应的请求」不会因为最后一条消息或整段窗口而引用错位。

### 3. 主动 Task 准入即关闭目标问题

`submitTask` 返回 `accepted=true` 后，立即对目标 wait 问题 `markSilenced`。问题不再进入后续 `pendingQuestions`，探针与后续人类消息不会对同一对象重复生成主动 Task。准入失败不关闭，保留重试机会。该关闭只是一次主动尝试的终止标记，不声称人类已回答；用户再次提问会登记新问题。

### 4. 长回复先给确定性索引

合并转发前的提示不再固定为「结果已整理」。程序从完整正文提取：首条非标题结论（最多 100 字）与最多 5 个章节/编号标题（每个最多 50 字），生成「结论 + 要点」短提示，并指向下方合并转发。索引不调用模型、不改写正文；正文仍完整保存在记录里。引用摘录在渲染时压成单行并截断到 120 字，避免合成上下文引用把回复撑长。

### 5. 内容安全错误单独说明

runner 把 `TurnOutcome.errorMessage` 带入失败 cause；前台固定回复按 cause 选择文案：命中 `inappropriate content` / `content filter` / `safety` 时说明「内容触发内容安全限制」，`TIMEOUT` 时说明超时。其他失败仍用「前台处理失败，请稍后重试。」，不暴露 provider、协议或内部路径。

### 6. 内容安全失败后刷新会话上下文

内容安全过滤失败时，出错输入本身仍在 `ConversationStore` 与观察窗口里；只换固定文案不解决问题——在窗口过期前，下一条消息的 `capture` 仍会按旧 `sinceTs` 把敏感内容回放/注入，模型会反复失败。`SessionActorV3` 在 Task 终态时检查前台失败与 worker 失败 cause；命中的，把该会话 `generation` 加一并把 `sinceTs` 推到该条输入之后（至少 `input.ts + 1`），不取消其他未完成任务。持久化失败只告警，不阻断 Task 终态。

这条刷新同时切断旧 Task 的 follow-up 关联；这是有意为之：敏感内容已被判定不能进入模型，保留旧上下文只会重复触发。普通失败、超时和取消不刷新。

## 影响与边界

- 公共契约、持久 schema、Task/lane 所有权、消息队列与预算不变；只改变提示组装、引用选择、问题状态和纯文本提示。
- 主动 Task 关闭问题后，若该 Task 后续失败，不会自动对同一问题再次主动发言；用户重新提问或新问题进入新台账。这是用「不重复刷屏」换「自动重试」，与现有 `maxQuestionProbes` 的收敛目标一致。
- 合成上下文引用仍是兜底；其摘录被截断后，正文不再包含整段上下文。
- 长回复的「完整正文」仍在合并转发中；索引只是入口，不是替代正文。

## 验收

- 单测覆盖：proactive 提示包含原引用且带「只回答」约束；主动 Task 准入后同一问题不再生成第二个 Task；长正文提示包含结论/要点与转发指路；引用摘录截断；内容安全 cause 映射为专用文案；内容安全失败后下一条 Task 进入新 generation。
- scene-1/scene-2 的 evidence 回查依赖真实窗口与判定 evidence，离线单测不伪造该组合；保留为现网重建后的定向复验项。
- `npm run typecheck`、相关 `vitest`、`npm run lint` 通过；`npm test` 为 67 个文件、1178 项通过、44 项按既有规则跳过。真实容器重建与现网复验另列，不在本次离线验收内。
